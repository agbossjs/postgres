**The connection is the application's `@DatabaseStorage`, nothing else** (agbossjs/agboss#1324b, the core's environment flip): `PostgresConnection` is `@Injectable({ deps: [DATABASE_SETTINGS] })` and reads no `ApplicationContext.environment` — `postgresUrl`, `postgresPoolSize`, `postgresSchema`, `postgresSchemaSetup`, `postgresWatchLivenessSeconds`, `postgresCommandTimeoutMs`, `postgresIdleInTransactionTimeoutMs`, `postgresAllowLiveLeases` and `environmentFields` are gone, and so is `settingsOfEnvironment`. Name the database with `@DatabaseStorage({ driver: PostgresDriver({ url: secret("POSTGRES_URL"), schema, poolSize, schemaSetup, timeouts }) })`; `new PostgresConnection(settings)` takes a `PostgresConnectionSettings` object (a script, a test) or the driver's resolved settings. An application that starts a PostgreSQL store with no `PostgresDriver` storage fails the start with `PostgresSettingsError` naming the storage to declare, before anything connects; a store class listed in `providers` beside a storage is the core's `[storage.providers-conflict]`. The fault set (`tests/faults/postgres.fault-stores.ts`) names `storage: { backend: "postgres", settings: { kind: "postgres", url: secret("AGBOSS_FAULT_DATABASE_URL"), poolSize: 4 } }` in place of `environment`. The process tests' applications have no `environment`; the `--env` / `{ env }` selections are gone.
